# Как собирать заявки с формы

Форма «Записаться на бесплатную диагностику» больше не ведёт в пустоту: заявка
попадает в базу Cloudflare D1 и приходит вам в Telegram.

## Как это работает

```
посетитель → POST на Worker → запись в D1
                          → уведомление в Telegram
                          → экран «Заявка отправлена»
```

Если Worker по какой-то причине не ответил, посетитель **видит правду**:
экран «Заявка отправлена» не появляется, форма остаётся заполненной, под
полями написано «попробуйте ещё раз». Показывать успех при недоступном
Worker нельзя — человек будет ждать звонка, которого не будет.

## Почему нельзя было просто вписать токен бота

Старая схема отправляла сообщение прямо из браузера:

```js
fetch('https://api.telegram.org/bot' + bot.token + '/sendMessage', ...)
```

`js/config.js` — публичный файл. Токен из него виден каждому посетителю в
DevTools, и по нему можно писать от вашего имени. Поэтому теперь токен лежит в
секретах Worker и в браузер не попадает.

## Развёртывание

### 1. База D1

Прямая ссылка: **dash.cloudflare.com → Workers & Pages → D1 SQL Database**

1. **Create Database** → имя `math-leads-db` → **Create**
2. Кликните по созданной базе в списке
3. Откройте вкладку **Console** (не SQL)
4. Вставьте содержимое
   [`cloudflare/leads-worker/schema.sql`](../cloudflare/leads-worker/schema.sql)
5. **Execute** → должно быть `3 commands executed successfully`

Вкладки внутри базы: **Console** (здесь SQL), **Tables** (список таблиц),
**Settings** (удаление базы). Вкладки с названием «SQL» в интерфейсе нет —
в документации Cloudflare её тоже нет, поэтому называть её «SQL» было
неверно, извините.

Если вкладки Console не видно — обновите страницу (Ctrl+F5): иногда после
создания базы список перерисовывается не с первого раза.

### 2. Worker

Прямая ссылка: **dash.cloudflare.com → Workers & Pages**

1. **Create application** → пункт **Worker** (не Pages)
2. Имя `math-leads` → **Deploy**. Worker сразу создастся с Hello World
3. Откройте его → иконка **Edit code** (`</>`) слева сверху, либо вкладка
   **Edit code**
4. **Удалите** содержимое редактора целиком — иначе останется Hello World
   поверх нашего кода
5. Вставьте
   [`cloudflare/leads-worker/worker.js`](../cloudflare/leads-worker/worker.js)
   целиком, от первой строки `/**` до последней `}`
6. **Save and deploy**

Копировать отсюда: файл открывается на GitHub кнопкой **Raw**, либо лежит
локально в `cloudflare/leads-worker/worker.js`.

### 2a. Привязка базы (Bindings)

Код обращается к базе как `env.DB` — значит **имя переменной должно быть
ровно `DB`**, заглавными буквами. Если назвать `db` или `DATABASE`, Worker
ответит «База не подключена».

В Worker `math-leads`:

1. Сверху вкладки: **Overview** · **Edit code** · **Settings** · **Deployments** ·
   **Logs** · **Metrics**. Откройте **Settings**
2. Слева список разделов: **General** · **Bindings** · **Variables and Secrets** ·
   **Triggers** … Откройте **Bindings**
3. Кнопка **Add binding**
4. Выпадающий список типа → **D1 Database**
5. Заполните два поля:

   | Поле | Что вписать |
   |---|---|
   | **Variable name** | `DB` — без пробелов, с большой буквы |
   | **D1 database** | выпадающий список → `math-leads-db` |

6. Кнопка **Add binding** (или **Deploy**) — зависит от версии дашборда,
   иногда сохранение происходит сразу

После этого в списке Bindings должна появиться строка **D1 Database: `DB`** →
`math-leads-db`.

**Проверка, что привязка работает.** Открытие корня этого не проверяет:
маршрут `/` базу не трогает и ответит `{"ok":true,...}` в любом случае.
Нужна настоящая заявка — в консоли браузера на странице вашего сайта:

```js
fetch('https://math-leads.<поддомен>.workers.dev/api/lead', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    name: 'Проверка связи', phone: '+79001112233',
    grade: '8', goal: 'тест', page: 'ручная проверка', website: ''
  })
}).then(r => r.json()).then(console.log);
```

Ожидается `{"ok":true,"id":1}`. Ошибка `{"ok":false,"error":"База не
подключена (переменная DB)"}` — имя переменной указано неверно.

Вкладки **Production** / **Previews Base** над таблицей привязок: привязка
добавляется в **Production**, этого достаточно.

Если Worker создан вручную в дашборде и вы платите за Workers Builds,
дашборд предложит синхронизировать привязку с `wrangler.jsonc`. Для этого
Worker можно согласиться — файл в репозитории не нужен, привязка живёт в
настройках самого Worker.

### 3. Секреты

Там же **Settings** → **Variables and Secrets** → **Add**.

1. Раскройте **Type** и выберите **Secret**. Не **Text** — значение Text
   будет видно в интерфейсе и в коде Worker'а
2. **Variable name** → впишите имя из таблицы ниже
3. **Value** → впишите значение, **Encrypt** отмечен по умолчанию
4. **Add variable** — добавляет следующее поле в той же форме, так все
   четыре секрета заводятся за один заход
5. **Deploy** — кнопка внизу формы. Без неё секреты сохранены, но не
   применены: Worker продолжает работать со старыми значениями

Имена пишутся ровно как здесь — код читает `env.TELEGRAM_BOT_TOKEN`,
`env.TELEGRAM_CHAT_ID`, `env.LEADS_TOKEN`, `env.ALLOWED_ORIGIN`.

#### `TELEGRAM_BOT_TOKEN` — токен бота

1. Откройте https://t.me/BotFather в Telegram
2. Нажмите **Start** (или отправьте `/start`)
3. Отправьте `/newbot` — для нового бота. Или `/token` — если бот уже создан,
   тогда переиспользуйте существующий
4. BotFather спросит имя, потом username, оканчивающийся на `bot`
5. В ответ придёт строка вида:

   ```
   Use this token to access the HTTP API:
   7123456789:AAHx...длинный-хвост
   ```

   Всё между `:` и концом строки — и есть значение. Само `Use this token
   to access the HTTP API:` вставлять не надо, копируйте только токен.

Токен выглядит так: `7123456789:AAH...`. Оставьте его у себя, он больше
нигде не понадобится — только в этом поле.

#### `TELEGRAM_CHAT_ID` — ваш чат с ботом

1. Откройте **своего** бота (не BotFather) и напишите ему любое сообщение,
   например `привет`. Без этого бот не знает, что чат существует, и
   `getUpdates` вернёт пустоту
2. Откройте в браузере, подставив свой токен:

   ```
   https://api.telegram.org/bot<ТОКЕН>/getUpdates
   ```

3. Найдите `"chat":{"id": 123456789,...}` — это число и есть значение.
   Впишите **только число**, без кавычек и без запятой

У обычного личного чата id положительный. Если хотите уведомления в группу,
id будет вида `-1001234567890`, с минусом — вписать надо со знаком.

Проверить, что бот пишет в этот чат, можно сразу:

```
https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=123456789&text=test
```

Если в Telegram придёт `test`, значит токен и id верные. Если придёт JSON с
`"ok":false` — смотрите поле `description`, там написана причина.

#### `LEADS_TOKEN` — пароль от выгрузки CSV

Значение нужно придумать/сгенерировать самостоятельно, взять его неоткуда.
Откройте PowerShell и выполните:

```powershell
$b = New-Object byte[] 24
[System.Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b)
($b | ForEach-Object { $_.ToString("x2") }) -join ''
```

Выведет 48 шестнадцатеричных символов — это и есть значение. Сгенерированный
мной вариант (берите его или свой, оба годится):

```
d44b5992cbf95a3c37e6241a4e7ecdad5c81b5f96919c414
```

Сохраните его в менеджере паролей: без него не открыть выгрузку заявок.
Своего токена в репозиторий не кладите.

#### `ALLOWED_ORIGIN` — адрес вашего сайта

```
https://math-tutor.varangian7221.workers.dev
```

Это просто адрес сайта: **без слеша в конце, без пути, без `www`**.
Без слеша — обязательно: сравнение идёт как есть, и с `/` все заявки будут
отклоняться с `403`. Если позже подключите свой домен, впишите его здесь и
передеплойте.

Несколько адресов в этом поле не поддерживаются — там одна строка. Если
сайт будет доступен по двум именам, оставьте то, с которого реально
приходят заявки.

### 4. Адрес Worker в конфиге сайта

`js/config.js`:

```js
leadsEndpoint: 'https://math-leads.<ваш-поддомен>.workers.dev/api/lead',
```

Пока строка пустая, форма честно скажет посетителю, что не работает, и
попросит позвонить. Задеплоить Worker и не спешить переключать сайт можно,
но заявки в это время не собираются.

## Как смотреть заявки

В D1 → ваша база → **Console**:

```sql
SELECT * FROM leads ORDER BY id DESC LIMIT 50;
```

Пометить обработанной после звонка:

```sql
UPDATE leads SET status = 'done' WHERE id = 42;
```

Выгрузка в Excel (CSV, разделитель `;`, кириллица в порядке):

```
https://math-leads.<поддомен>.workers.dev/api/leads.csv?key=<ваш LEADS_TOKEN>
```

Ссылка с токеном — секрет. Не пересылайте её и не публикуйте: по ней видны
телефоны всех посетителей.

## Защита от спама

| Приём | Что делает |
|---|---|
| honeypot | скрытое поле; человек его не видит, бот заполняет — заявка отбрасывается |
| лимит по IP | не больше 5 заявок за 10 минут с одного адреса |
| проверка Origin | отсекает чужие страницы в браузере |

Честно про Origin: **это слабая проверка, а не защита.** Любой скрипт просто не
пришлёт этот заголовок и пройдёт. Реальную работу делают honeypot и лимит по IP.
Если формы начнут засыпать мусором — добавьте капчу.

Honeypot сделан через `position:absolute; left:-9999px`, а не `display:none`:
часть ботов невидимые поля пропускает, а за границу вьюпорта полезть не может.

## Что сохраняется

`name`, `phone`, `grade`, `goal`, `page`, `ip`, `user_agent`, `created_at`,
`status`. Плюс Telegram-уведомление вам.

Телефон пишется в том виде, в каком его ввели, вместе с маской. IP сохраняется
для разбора спама — если он не нужен, уберите колонку из `INSERT` в Worker.

## Проверено

Worker прогнан локально как обычный модуль, с подставной базой:

| Проверка | Результат |
|---|---|
| нормальная заявка | `200`, запись в базу, `id` возвращается |
| honeypot заполнен | `200 {ok, skipped}` — в базу не пишется |
| телефон короткий | `400` с понятным текстом |
| имя короче 2 символов | `400` |
| чужой Origin | `403` |
| без Origin (curl) | `200` — поэтому Origin и не защита |
| 6-я заявка за 10 минут | `429` |
| `GET` вместо `POST` | `405` |
| CSV без токена / с чужим | `401` |
| CSV с именем `Мария;Иван"Оля"` | кавычки и `;` экранированы, BOM на месте |

Фронтенд проверен отдельно: payload собирается верно, экран успеха
показывается только при ответе `2xx`, кнопка разблокируется, при сбое
форма остаётся заполненной и просит повторить.
